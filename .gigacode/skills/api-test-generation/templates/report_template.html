Откуда берутся AC и тесты (пайплайн api-test-generation): AC выделяет requirements-analyst; test-case-designer группирует их в TC и закрепляет, каким тестом какой AC закрывается; test-generator пишет код; test-reviewer проверяет 1-в-1; test-validator прогоняет.
AC больше тестов, т.к. один тест проверяет несколько правил. Пример — «{{создание_сущности}}» за один запрос закрывает «200», «все обязательные поля», «требует {{обязательное_поле}}». Поэтому {{Σ_TC}} сценариев закрывают {{покрыто_AC}} правил — это нормально.
Это не «сколько тестов прошло», а полнота страховки. Итог — карточки «Тесты {{Σ_passed}} passed». Оставшийся AC вынесен на ручную (стенд отвечает некорректно).
