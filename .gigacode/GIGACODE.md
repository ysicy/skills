# GigaCode Rules

## Как сгенерировать автотест

По тест-кейсу Jira/Zephyr:

```
Сгенерируй автотест по кейсу: https://jira.sberbank.ru/secure/Tests.jspa#/testCase/<PROJECT_KEY>-TXXXX
```

По Swagger/OpenAPI (модели генерируются из спецификации через `openapi_tool`):

```
Сгенерируй автотесты по Swagger: https://petstore3.swagger.io/api/v3/openapi.json
```

Запрос обрабатывает скилл `api-test-generation` (`.gigacode/skills/api-test-generation/SKILL.md`) — пайплайн из 7 субагентов:

```
code-pattern-matcher → requirements-analyst → test-case-designer → test-generator → test-reviewer → test-fixer → test-validator
```

Итог: автотест в `<test_suites>/test_<feature>.py`, сводка прогона `.gigacode/design/report.json` и накопительный дашборд `.gigacode/design/test-report.html`. Allure-отчёт не генерируется.

## Где лежат тесты

- Один эндпоинт — один файл `test_<feature>.py` (имя по смыслу проверки). Все кейсы на этот эндпоинт дописываются в тот же файл; кейс на новый эндпоинт — новый файл.
- Существующие тесты, классы, фикстуры и константы не изменяются и не удаляются: новый тест только добавляется рядом, без дублирования того, что уже есть в файле.

## Автономность

Пайплайн работает без подтверждений: команды (`python -m pytest`, `openapi_tool`, `git`), правки файлов и переходы между агентами выполняются без вопросов вида «можно выполнить?» или «продолжать?». Тест запускается автоматически на шаге валидации.

Пользователя спрашивают только при внешнем блокере:
- не хватает входных данных (тело запроса, параметры, URL, тест-кейс);
- нет доступа к стенду или он стабильно отвечает 4xx/5xx из-за данных;
- требование неясно и не выводится из кода;
- исчерпаны лимиты (4 цикла ревью, 4 итерации валидации).

После ответа пайплайн продолжается с того же агента.

## Test Case Fidelity

Каждый шаг тест-кейса — свой Allure-шаг, каждый ожидаемый результат — своя проверка. Проверок, которых нет в кейсе, не добавлять, даже если они «очевидно нужны». Полное правило — `.gigacode/design/common-principles.md`.

## Правила скилла

- `.gigacode/design/common-principles.md` — общие правила для всех агентов. Постоянный файл: доставляется каждому агенту; если его нет, скилл повреждён — сообщи оператору.
- `.gigacode/agents/<agent>.md` — правила каждой роли.
- `.gigacode/skills/api-test-generation/SKILL.md` — правила оркестратора.
- `code-patterns.json` и другие файлы в `.gigacode/design/` — продукты прогона. Их отсутствие штатно: агенты определяют контур проекта сами.
